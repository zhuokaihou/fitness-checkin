# 健身打卡 · Fitness Check-in

一个中文优先、手机可用的自托管健身与餐食打卡应用。每个部署只服务一个个人账户，数据保存在自己的 SQLite 数据库中。模型分析是可选功能；不配置 API 也能正常记录、看趋势与导出。

- 90天通用四分化模板：胸＋三头、背＋二头、有氧、腿、肩＋核心、有氧、休息。
- 每餐完成状态及实际食物/份量，每个动作实际重量、工作组数、各组次数与完成状态。
- 有氧时间/距离、步数、睡眠、疲劳、晨重、腰围与备注，按周显示体重趋势。
- 日期与体重/步数/能量/蛋白质目标由使用者设置；新账户无实测体重、无预填营养目标。支持留空、维持或增重目标。
- 自配 OpenAI 兼容 API：配置、删除、连接测试；单日及7/14天趋势分析，先预览摘要并确认费用与发送范围，再调用模型。
- JSON / CSV 记录导出，动态生成通用计划 Excel，数据库一致性备份与恢复。

通用模板只是记录示例，请按个人经验与恢复情况调整。餐食描述来自手动输入，营养只能估算；缺失项不当作零。不读取 Apple 健康或其他健康平台，不提供诊断。模型可能出错，不应根据单日体重波动补偿性节食或加练。

## 快速开始：本地运行（无需安装依赖）

需要 Python 3.12 或更高版本；标准库即可运行开发服务。

```sh
python3 manage.py create-owner --username my_owner
# 交互输入自己的密码（至少12字符，无通用密码）
PUBLIC_URL=http://127.0.0.1:8080 SECURE_COOKIE=false python3 app.py
```

打开 <http://127.0.0.1:8080>，登录后在「设置」调整计划。开发服务仅监听本机；仅用于本地使用，生产用 Gunicorn + HTTPS。账户创建不会启动公开注册页面。

`.env` 是 Compose 的配置文件，Python 直接运行不自动加载；直接运行时通过环境变量配置。默认 `SECURE_COOKIE=true`，本地 HTTP 需明确设为 `false`。

## 参与开发

后端为 Python 标准库 WSGI + SQLite，前端是原生 JavaScript + CSS，无前端构建步骤。生产依赖固定在 `requirements.txt`。从项目根目录执行：

```sh
python3 -m unittest discover -s tests -v
node --check static/app.js
```

测试只使用临时数据库与回环模拟 API，不使用真实付费模型。不要提交 `.env`、`data`、数据库、备份、日志或浏览器认证状态；提交前可运行 `python3 scripts/audit_public.py`。
